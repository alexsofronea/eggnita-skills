# Create — the positioning workflow

Build positioning the way the method actually runs: anchors → options → canvas → page. Five stages, each gated (the user confirms before the next; the panel is available at each). The deliverables you promised — a brief, homepage copy, a wireframe spec — fall out of it: the **Canvas is the brief**, the color-coded homepage is the **copy**, the section plan is the **wireframe**.

Everything here is built on the grammar in [anchors.md](anchors.md) and the fill-in structures in [templates.md](templates.md).

## Stage 0 — Discovery

Run [discovery.md](discovery.md) — a six-question anchor intake that finds the primary anchor containing a real problem. No stage below proceeds on unconfirmed assumptions.

## Stage 1 — (Repositioning only) Document what's wrong

If something already exists, first write down the concrete problems with the current positioning — in specifics, not vibes. *(Freckle: "many of our best users are actually technical"; "our happiest customers aren't here for outbound.")* This is a mini-audit ([audit.md](audit.md)) that frames what the reposition must fix. Skip for net-new.

## Stage 2 — Map 2–3 options (Anchor + Value), each with Thesis + Risks

Don't jump to one answer. Generate **2–3 whole positioning directions** using the options-map in [templates.md](templates.md#3-the-anchor--value-options-map): each with its anchors + value, a color-coded sample hero, and an explicit **Thesis** (what must be true for this to win) and **Risks** (who it alienates, what could break it).

This is the highest-leverage stage. You choose by **thesis and risk, not by testing** — positioning can't be A/B tested ([frameworks.md](frameworks.md#17)). **Offer the panel here**: the critic attacks each thesis, ICP personas react to each hero. Present the options, recommend one with reasoning, let the user choose.

## Stage 3 — Fill the Positioning & Messaging Canvas

Take the chosen direction and build the full **Canvas** ([templates.md](templates.md#1-the-positioning--messaging-canvas)): the five anchors, the Problem Summary linked to one primary anchor, the Differentiation Summary, and one argument column per supporting point (sub-problem → pillar → capability → features → benefit, 1:1 linked).

The completed Canvas **is the positioning brief** — the load-bearing artifact. If it's weak, the page inherits the weakness. Offer the panel; confirm. *(Optionally also produce the [6-slide deck](templates.md#2-the-6-slide-positioning-deck) for internal alignment.)*

## Stage 4 — Translate the Canvas into homepage copy

Turn the Canvas into section-by-section copy, following the homepage anatomy in [patterns.md](patterns.md) (hero → social proof → problem → positioning/category line → capability blocks → differentiation → package → self-qualification → proof → process/CTA). Each argument column becomes a product section; the hero states a primary anchor and passes the 5-second test.

Words are paste-ready, plain, customer-centric — built from the formulas in [exemplars.md](exemplars.md). **Color-code the copy to the Canvas** ([templates.md](templates.md#governance-color-code-the-copy)): every line must map to a cell, or it's off-strategy. **Run the copy through the `stop-slop` skill before presenting it** (SKILL.md: "Always run the slop check") — generated positioning copy that reads like AI slop is dead on arrival. Offer the panel; confirm.

## Stage 5 — Wireframe spec

The layout a designer or a frontend skill can build. Structure and intent, not visual design.

- **Section order** — the sequence and why (problem → action narrative).
- **Each section's job** — what it accomplishes and which Canvas cell it carries.
- **Content slots** — headline / subhead / body / media / proof / CTA per section, with the Stage 4 copy dropped in.
- **Hand-off note** — hooks for `frontend-design` or a designer. egg-superposition stops here; it doesn't build the page.

## Beyond the page (offer, don't assume)

Positioning isn't just the homepage — it's one narrative carried across the whole GTM over months (see positioning-as-a-timeline, [frameworks.md](frameworks.md#18)). If the user wants it, extend the Canvas message into channel copy (outbound, cold email, ads) and name the champion-first sales motion. Offer; don't force.

## Stage gating

- Each stage ends with: present → offer panel → confirm → proceed. Never chain silently.
- The user can stop at any stage (options only, Canvas only, or Canvas + copy). Stages 4–5 are optional if they just wanted the strategy.
- If discovery shows the real job is fixing an existing page, switch to [audit.md](audit.md).
